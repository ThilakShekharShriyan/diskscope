05 · Limits

What this does and doesn't show

A fresh microVM reading a file is fresh-execution visibility, not the directory-cache behaviour of a long-lived mounted client; that is a separate experiment.

Archil commits a writing exec at exit (~70 ms), so a fresh-VM read after write-fsync can't separate fsync durability from that commit. No host failure is injected.

SQLite uses journal_mode=TRUNCATE: the default DELETE and WAL fail across execs on Archil (finding #2). Cleanup uses a conditional mount for the same reason.

Writers never share a file; this is single-writer-per-path. Small n — a smoke-level baseline, not a statistical result. No disks, branches or checkpoints are created.
