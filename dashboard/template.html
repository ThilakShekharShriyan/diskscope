Anatomy of a serverless call

Archil reports queue and execute time for every call; the guest times its own work; the client times the round-trip. Default image first, then a no-op on every other exec configuration.

Segments are per-phase medians, so they sum to roughly — not exactly — the median total. 09 · Platform findings

What we reported to Archil

Each is reproducible with a few curl calls — full repros in ARCHIL-FINDINGS.md.

Default execs can't delete earlier files

The single-disk exec mount holds no delegation checkout, so removing anything an earlier exec created fails — reported as a misleading EROFS. checkoutPaths or a conditional mount fixes it.

SQLite breaks across execs

A database created in one exec gets disk I/O error on the next exec's commit and is then unreadable from a default exec. Check out the directory, or use journal_mode=TRUNCATE.

Writes pay a commit at exit

A shell command that writes one file has ~70 ms more execute time than true (76 ms vs 4 ms). A persistent sandbox worker avoids it.

The image choice is a 4.5× queue difference

Default image: ~32 ms queue from the warm pool. python:3.13-slim: ~145 ms, booted on demand. The default image already ships Python 3.10.

11 · Methodology

How to read these numbers

Design follows Hoefler & Belli's rules for reporting performance, criterion.rs, hyperfine, fio and ClickBench practice.

Statistics

  • Medians, never mean ± σ: latency is skewed and bounded at zero.
  • Median intervals from order statistics: exact coverage, no distributional assumptions.
  • Ratios use a seeded two-sample bootstrap (labelled approximate at these n).
  • Configurations are never pooled; no outliers are removed.

Fairness

  • Identical Python guest everywhere; cross-environment ratios use guest-measured work only.
  • Local fsync uses F_FULLFSYNC so both sides pay for durability.
  • Every v0.2 run shuffles (task, trial) order and records the seed.
  • Warm-up and sandbox boot are recorded but excluded from statistics.

Limits

  • One region, one client, one disk; n = 5–10 per cell.
  • Fan-out is closed-loop: no throughput-at-load claims.
  • seq-read is warm-cache; no cold-read claims.
  • A sandbox's plain mount holds the disk exclusively while it runs.
